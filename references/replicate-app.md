# 仿作模式 · 照着现有 App / 安装包 / 截图 / 文字描述做一个

当用户说"做一个像 XX / 仿 XX"，**或上传了一个 apk / exe / 截图**，**或用文字描述想要的功能**时，进入**仿作模式**。

核心原则：**先模仿其"形"（界面、图标、入口 Activity、布局），功能（必做 / 可选 / 不做）由开发者自己想，或你帮它大致推测里面有什么，再让开发者拍板。** 仿作是"做出同等体验的最小实现"，不是逐像素复刻。

## 触发信号

- "做一个像 <App 名> 的" / "仿 <App 名>" / "照着 <App 名> 做一个"
- 用户**上传了一个 apk**
- 用户**上传了一个 exe**（跨平台参照其 UI）
- 用户**上传了一张截图**
- 用户**用文字描述功能**（"我要一个能 XX 的 App"）
- "XX 挺好用，给我来一个"

只要用户拿某个**已存在的 App / 安装包 / 截图 / 一段功能描述**当参照，就走这一节，不要直接进入选型。

## 五种参照物，怎么取"形"

| # | 参照物 | 怎么"模仿其形" | 功能从哪来 |
|---|---|---|---|
| 1 | App 名（"像 XX"） | 让开发者描述，或你按常识给 UI 草图 | 开发者定 / 你推测 |
| 2 | 上传的 **apk** | 用工具链 `aapt2 dump badging` 取包名、入口 Activity、权限、特性、图标；看 res 布局与 strings | 从权限 / Activity / 字符串**推测**，开发者确认 |
| 3 | 上传的 **exe**（跨平台参照其 UI） | 看图标、版本信息、界面截图，把 Windows 软件的形态搬到 Android | 从界面与同类 App 推测，开发者确认 |
| 4 | 上传的**截图** | 直接照布局 / 配色 / 控件复刻界面 | 开发者定 / 你推测 |
| 5 | **用户文字描述的功能** | 功能已由用户给出，形由你给 UI 草图或参照同类 App | 功能已由用户描述，你来落地 |

> 形态 2/3/4 是"先有形"；形态 1/5 是"先有功能，你来补形"。两条路都行，最终都汇成「形 + 功能清单」。

## 必须一次性追问的功能点

用 AskUserQuestion 或一轮连续的提问，把功能拆成三档。不要挤牙膏式追问。

| # | 要问的 | 为什么 |
|---|---|---|
| 1 | 参照物是 App 名 / apk / exe / 截图 / 文字描述？ | 决定上面怎么取"形" |
| 2 | 你最在意它的哪一点？ | 抓住"灵魂"，避免被表面 UI 带偏 |
| 3 | **必做**的核心功能（逐条列出） | 圈定 MVP，第一版只做这些 |
| 4 | 可以**砍掉 / 简化**的功能 | 先做最小可用，后续再迭代 |
| 5 | 目标设备形态（手机 / 电视 / 平板 / 盒子） | 复用 SKILL.md 阶段 0 的设备形态 |
| 6 | 有没有界面参考（截图 / 描述 / 配色） | 减少来回确认，直接对齐观感 |
| 7 | 数据从哪来？要不要**兼容原 App 的数据 / 文件格式**？ | 决定是否要解析旧数据库 / SharedPreferences / 私有文件 |
| 8 | 要哪些权限、要不要联网 | 权限必须在 manifest 声明，运行时还要授权 |
| 9 | 用哪把签名证书 | 复用你的个人证书，否则无法覆盖升级 |

## 产出格式

一份不超过 15 行的清单，分三档：

```
定位：做一个像 <App> 的 <一句话>
设备：手机 / 电视 / 平板 / 盒子
形：界面草图（顶部栏 / 列表 / 卡片 / 按钮 / 配色）——从参照物取
必做：
  - 功能 A
  - 功能 B
可选（后续迭代）：
  - 功能 C
不做（第一版砍掉）：
  - 功能 D（原 App 有，但本次不需要）
数据：本地 SharedPreferences / SQLite / 联网 API
权限：相机 / 存储 / 联网（仅列必需）
```

拿到这份清单后，再进入 SKILL.md 阶段 1 选型（默认命令行链；需要第三方库才上 Gradle）。

## 从安装包 / 截图 / 文字推测功能的线索

- **apk**：`aapt2 dump badging` 后看 `uses-permission`——`CAMERA`→拍照、`INTERNET`→联网、`READ_CONTACTS`→通讯录、`WRITE_EXTERNAL_STORAGE`→文件操作、`ACCESS_FINE_LOCATION`→定位；入口 Activity 数量暗示有几个页面；`res/values/strings.xml` 里的词暴露功能点。
- **exe**（跨平台参照）：把 Windows 软件的界面形态搬到 Android——顶部栏 / 列表 / 卡片；功能按同类 App 常识推测。
- **截图**：直接照布局复刻——顶部栏 / 侧边栏 / 列表 / 按钮 / 配色，先出静态骨架。
- **文字描述**：功能已由用户给出，重点是帮他把"描述"翻译成"必做 / 可选 / 不做"三档，并补上界面草图。

> 推测只是辅助，最终由开发者确认。不要替用户拍板功能范围。

## 示例 1：做一个像"系统备忘录"的本地笔记 App

追问后得到：

```
定位：轻量本地笔记
设备：手机
形：列表页（笔记标题+时间）+ 编辑页（标题+正文）
必做：
  - 新建 / 编辑 / 删除笔记
  - 列表展示 + 按修改时间排序
  - 本地持久化（SQLite 或 SharedPreferences）
可选：
  - 搜索 / 置顶加星
不做：
  - 云同步（不联网）
  - 富文本 / 图片
数据：本地 SQLite
权限：无（纯本地）
```

→ 命令行链即可；minSdk 21；无联网权限；个人证书签名。

## 示例 2：上传一个 apk，仿它的文件管理器

用户丢来 `filemgr.apk`：

```
aapt2 dump badging filemgr.apk
  package: com.xx.filemgr
  launchable-activity: .MainActivity
  uses-permission: READ_EXTERNAL_STORAGE, WRITE_EXTERNAL_STORAGE
```

推测：读写存储 → 本地文件浏览/管理。用户只想要"浏览+基础管理"，砍掉压缩/网络：

```
定位：本地文件浏览与管理
设备：手机 / 平板
形：目录树 + 文件列表（图标+名称+大小）
必做：
  - 浏览内部存储目录树
  - 复制 / 移动 / 删除 / 重命名
  - 查看文本 / 图片
可选：
  - 压缩 / 解压 / 按类型筛选
不做：
  - 局域网 / FTP / 云盘（不联网）
  - 应用管理
数据：直接操作文件系统
权限：READ/WRITE_EXTERNAL_STORAGE（Android 10+ 用 SAF）
```

→ 注意 Android 10+ 存储权限变化，优先用 SAF（Storage Access Framework）而非旧权限。

## 原则

- **仿作 ≠ 复刻**：做出同等体验的最小实现，先交付能装的，再迭代。
- **形先功能后**：先交"形"（界面骨架 + 图标 + 入口），功能（必做 / 可选 / 不做）由开发者自己想，或你帮它大致推测里面有什么，再让开发者拍板。
- **功能 > 界面**：先定必做功能，界面只是载体。
- **敢砍**：用户说"像 XX"时往往只想要 XX 的某一个点，帮他把其它点砍掉。
- **数据兼容要问**：很多仿作掉坑在"要不要读原 App 的数据"，这一条一定要问。
- **证书复用**：仿作 App 也要签你自己的个人证书，否则无法覆盖升级。
- **推测要标注**：从安装包/截图推测的功能只是辅助，务必让开发者确认，别替他拍板。
